\section{Introduction}

This document explores various primality testing methods in the context of Zero Knowledge Proofs (ZKPs). Each method is described in detail, including its algorithm, pseudocode, advantages, disadvantages, and its behavior for large numbers. The aim is to understand how these tests can be used for cryptographic applications and their suitability for ZKP systems.

\section{Fermat Primality Test}

\subsection*{Algorithm Explanation}

The Fermat Primality Test is a simple and efficient probabilistic method for checking if a number \( n \) is likely to be prime. It is based on \textbf{Fermat's Little Theorem}, which states:

\[
\text{If } n \text{ is prime and } a \text{ is an integer such that } 1 \leq a < n, \text{ then: }
\]
\[
a^{n-1} \equiv 1 \pmod{n}.
\]

The algorithm randomly selects integers \( a \) (called bases) within the range \( [1, n-1] \) and checks whether the above condition holds. If it fails for any base \( a \), \( n \) is composite. If it holds for several bases, \( n \) is declared as \emph{probably prime}.

\subsection*{Pseudocode}

\textbf{Fermat Primality Test}

% \texttt{Input: Number \( n \) to test, Number of iterations \( k \)}  
% \texttt{Output: "Composite" if \( n \) is composite; "Probably Prime" if \( n \) passes all tests}

\begin{quote}\ttfamily
1. If \( n \leq 1 \), return "Composite" \\
2. For \( i = 1 \) to \( k \) do: \\
\hspace*{2em} a. Randomly choose an integer \( a \) such that \( 1 \leq a < n \) \\
\hspace*{2em} b. Compute \( x = a^{n-1} \mod n \) \\
\hspace*{2em} c. If \( x \neq 1 \), return "Composite" \\
3. If all tests passed, return "Probably Prime"
\end{quote}

\subsection*{Advantages}

\begin{itemize}
    \item \textbf{Efficiency}:
    \begin{itemize}
        \item Computationally efficient with complexity \( O(k \cdot \log(n)^2) \), where \( k \) is the number of iterations and \( \log(n) \) is the cost of modular exponentiation.
        \item Suitable for small to medium-sized numbers.
    \end{itemize}
    \item \textbf{Simplicity}: Easy to implement with minimal additional mathematical knowledge.
    \item \textbf{Scalability}: Works well with modern hardware for moderately large numbers.
\end{itemize}

\subsection*{Disadvantages}

\begin{itemize}
    \item \textbf{Pseudoprimes}: Some composite numbers (called \emph{Fermat pseudoprimes}) pass the test for specific bases \( a \).
    \item \textbf{Base Dependence}: The result depends on the choice of base \( a \); poor selection of bases can lead to incorrect results.
    \item \textbf{No Certificate of Primality}: The test does not provide a deterministic proof or certificate of primality.
\end{itemize}

\subsection*{Advantages Over Trial Division}

The Fermat test outperforms trial division for numbers larger than \( 10^6 \). While trial division requires \( O(\sqrt{n}) \) checks for divisibility, Fermat operates with \( O(k \cdot \log(n)^2) \) complexity, making it faster for large inputs.

\subsection*{Behavior for Large Numbers}

\begin{itemize}
    \item Modular exponentiation ensures efficient computation for large numbers.
    \item The probability of declaring a composite number as "Probably Prime" decreases exponentially with the number of iterations \( k \).
    \item For \( k \) iterations, the error rate is at most \( 1 / 2^k \), assuming bases are chosen uniformly at random.
\end{itemize}

\subsection*{Expected Error}

\begin{itemize}
    \item \textbf{Error Rate}: At most \( 1 / 2^k \), where \( k \) is the number of iterations.
    \item \textbf{Worst-Case Error}: For Carmichael numbers (a special class of pseudoprimes), all bases \( a \) with \( \gcd(a, n) = 1 \) incorrectly pass the test.
\end{itemize}

\subsection*{Example}

Test \( n = 561 = 3 \cdot 11 \cdot 17 \), the smallest Carmichael number, with several bases (all values checked by computer):
\begin{itemize}
    \item \( 2^{560} \equiv 1 \pmod{561} \) and \( 5^{560} \equiv 1 \pmod{561} \): both bases pass, although \( 561 \) is composite.
    \item \( 3^{560} \equiv 375 \pmod{561} \) and \( 11^{560} \equiv 154 \pmod{561} \): these bases share a factor with \( 561 \) and expose it.
\end{itemize}
A Carmichael number passes the test for every base coprime to it, so the test only detects \( 561 \) if it happens to draw a base that is \emph{not} coprime to it. This is the limitation that the later tests address.

\subsection*{Conclusion}

The Fermat Primality Test is a fast and simple probabilistic test for identifying prime numbers. However, its susceptibility to pseudoprimes makes it less reliable for applications requiring absolute certainty, such as cryptography.



\section{Lehmann Primality Test}

\subsection*{Algorithm Explanation}

The Lehmann Primality Test builds upon Fermat's Little Theorem but includes an additional condition to address some of the shortcomings of the Fermat test, such as its susceptibility to pseudoprimes.

For a number \( n \) to be prime, and a chosen base \( a \), the following must hold:

1. \( a^{n-1} \equiv 1 \pmod{n} \)
2. \( a^{(n-1)/2} \equiv \pm1 \pmod{n} \)

If \( a^{(n-1)/2} \not\equiv \pm1 \pmod{n} \), then \( n \) is composite. By testing with multiple random bases, the probability of error can be reduced significantly.

\subsection*{Pseudocode}

\textbf{Lehmann Primality Test}

% \texttt{Input: Number \( n \) to test, Number of iterations \( k \)}  
% \texttt{Output: "Composite" if \( n \) is composite; "Probably Prime" if \( n \) passes all tests}

\begin{quote}\ttfamily
1. If \( n \leq 1 \), return "Composite" \\
2. For \( i = 1 \) to \( k \) do: \\
\hspace*{2em} a. Randomly choose an integer \( a \) such that \( 1 \leq a < n \) \\
\hspace*{2em} b. Compute \( x = a^{(n-1)/2} \mod n \) \\
\hspace*{2em} c. If \( x \neq 1 \) and \( x \neq n-1 \), return "Composite" \\
3. If all tests passed, return "Probably Prime"
\end{quote}

\subsection*{Advantages}

\begin{itemize}
    \item \textbf{Increased Accuracy}: By adding the second condition \( a^{(n-1)/2} \equiv \pm1 \pmod{n} \), the Lehmann test catches more composites compared to the Fermat test.
    \item \textbf{Efficiency}: Still retains a time complexity of \( O(k \cdot \log(n)^2) \), where \( k \) is the number of iterations.
    \item \textbf{Simplicity}: Easy to implement and provides more reliable results than Fermat.
\end{itemize}

\subsection*{Disadvantages}

\begin{itemize}
    \item \textbf{Probabilistic Nature}: Like Fermat, the Lehmann test is probabilistic and cannot guarantee primality.
    \item \textbf{Dependency on Randomness}: Its accuracy depends on the quality of the random number generator for selecting bases.
    \item \textbf{No Certificate of Primality}: The Lehmann test does not produce a verifiable certificate of primality.
\end{itemize}

\subsection*{Advantages Over Fermat Test}

\begin{itemize}
    \item By checking \( a^{(n-1)/2} \equiv \pm1 \pmod{n} \), the Lehmann test detects pseudoprimes that would otherwise pass the Fermat test.
    \item Significantly reduces the error rate compared to Fermat.
\end{itemize}

\subsection*{Behavior for Large Numbers}

\begin{itemize}
    \item Handles large numbers efficiently using modular exponentiation for calculations.
    \item For \( k \) iterations, the probability of a composite number passing as "Probably Prime" is at most \( 1 / 2^k \), assuming uniformly random bases.
\end{itemize}

\subsection*{Expected Error}

\begin{itemize}
    \item \textbf{Error Rate}: At most \( 1 / 2^k \), where \( k \) is the number of iterations.
    \item \textbf{Worst-Case Error}: The Lehmann test is still susceptible to Carmichael numbers, but the second condition reduces the chances of error compared to Fermat.
\end{itemize}

\subsection*{Example}

Test \( n = 341 = 11 \cdot 31 \) (a Fermat pseudoprime to base \( 2 \)); here \( (n-1)/2 = 170 \). All values checked by computer:
\begin{itemize}
    \item \( 2^{170} \equiv 1 \pmod{341} \): base \( 2 \) passes.
    \item \( 3^{170} \equiv 67 \pmod{341} \), which is neither \( 1 \) nor \( 340 \): base \( 3 \) exposes \( 341 \) as composite.
\end{itemize}
Base \( 2 \) alone declares \( 341 \) ``probably prime''; a second base is enough to reject it.

\subsection*{Conclusion}

The Lehmann Primality Test improves upon Fermat by adding an additional condition to reduce the likelihood of errors. While still probabilistic, it is more reliable than Fermat and is well-suited for applications requiring quick primality checks for moderately large numbers.

\section{Rabin-Miller Primality Test}

\subsection*{Algorithm Explanation}

The Rabin-Miller Primality Test is a probabilistic algorithm widely used to test primality. It improves on the Lehmann test by using the concept of nontrivial square roots of 1 modulo \( n \). The test is based on the following properties:

1. Decompose \( n-1 \) as \( 2^s \cdot d \), where \( d \) is odd.
2. A number \( n \) is composite if for a randomly chosen base \( a \):
   - \( a^d \not\equiv 1 \pmod{n} \), and
   - \( a^{2^r \cdot d} \not\equiv -1 \pmod{n} \) for all \( r \) in \( [0, s-1] \).

If \( n \) passes the above conditions for several random bases, it is declared as \emph{probably prime}.

\subsection*{Pseudocode}

\textbf{Rabin-Miller Primality Test}

% \texttt{Input: Number \( n \) to test, Number of iterations \( k \)}  
% \texttt{Output: "Composite" if \( n \) is composite; "Probably Prime" if \( n \) passes all tests}

\begin{quote}\ttfamily
% 1. If \( n \leq 1 \), return "Composite" \\
% 2. Write \( n-1 \) as \( 2^s \cdot d \) with \( d \) odd \\
% 3. For \( i = 1 \) to \( k \) do: \\
\hspace*{2em} a. Randomly choose an integer \( a \) such that \( 1 \leq a < n \) \\
\hspace*{2em} b. Compute \( x = a^d \mod n \) \\
\hspace*{2em} c. If \( x = 1 \) or \( x = n-1 \), continue to the next iteration \\
\hspace*{2em} d. Repeat \( s-1 \) times: \\
\hspace*{4em} i. Compute \( x = x^2 \mod n \) \\
\hspace*{4em} ii. If \( x = n-1 \), break \\
\hspace*{2em} e. If \( x \neq n-1 \), return "Composite" \\
4. If all tests passed, return "Probably Prime"
\end{quote}

\subsection*{Advantages}

\begin{itemize}
    \item \textbf{High Accuracy}: The test detects most composites that would pass Fermat or Lehmann tests.
    \item \textbf{Efficiency}: Modular exponentiation ensures the test is computationally efficient, with complexity \( O(k \cdot \log(n)^2) \).
    \item \textbf{Widely Used}: A practical and reliable algorithm for many cryptographic applications.
\end{itemize}

\subsection*{Disadvantages}

\begin{itemize}
    \item \textbf{Probabilistic Nature}: Like Fermat and Lehmann, Rabin-Miller cannot provide a deterministic proof of primality unless all possible bases are tested.
    \item \textbf{Computational Cost}: Slightly more computationally intensive than Fermat or Lehmann due to the additional checks.
    \item \textbf{Carmichael Numbers}: It can still fail for carefully constructed pseudoprimes, though the likelihood is extremely low.
\end{itemize}

\subsection*{Advantages Over Lehmann Test}

\begin{itemize}
    \item Incorporates multiple rounds of squaring, reducing the chance of error compared to the Lehmann test.
    \item Detects nontrivial square roots of 1 modulo \( n \), which many pseudoprimes would otherwise pass in Lehmann.
\end{itemize}

\subsection*{Behavior for Large Numbers}

\begin{itemize}
    \item Efficiently handles large numbers using modular exponentiation for both the initial test and subsequent rounds.
    \item For \( k \) iterations, the probability of error decreases exponentially, making the test suitable for cryptographic applications.
\end{itemize}

\subsection*{Expected Error}

\begin{itemize}
    \item \textbf{Error Rate}: At most \( 1 / 4^k \), where \( k \) is the number of iterations.
    \item \textbf{Worst-Case Error}: Although extremely unlikely, certain pseudoprimes may pass as "Probably Prime."
\end{itemize}

\subsection*{Example}

Test \( n = 561 \) with \( n-1 = 560 = 2^4 \cdot 35 \) and base \( a = 2 \).

\begin{itemize}
    \item Compute \( x = 2^{35} \mod 561 \):
    \[
    x \equiv 263 \pmod{561}
    \]
    \item Square \( x \) four times (since \( s = 4 \)):
    \[
    x^2 \mod 561 = 166, \quad x^4 \mod 561 = 67, \quad x^8 \mod 561 = 1
    \]
    \item Since \( x^{2^r \cdot d} \not\equiv -1 \pmod{561} \) for any \( r \), \( n \) is composite.
\end{itemize}

\subsection*{Conclusion}

The Rabin-Miller Primality Test is a powerful probabilistic method for primality testing. Its ability to detect nontrivial square roots of 1 modulo \( n \) makes it far more reliable than Fermat and Lehmann tests. While it remains probabilistic, its high accuracy and efficiency make it the preferred choice for practical primality testing, especially in cryptographic applications.

\section{Pratt Primality Certificate}

\subsection*{Algorithm Explanation}

The Pratt Primality Certificate is a deterministic algorithm that provides a verifiable certificate of primality. It is based on Lucas's theorem, which states:

\[
\text{A number } n \text{ is prime if there exists a base } a \text{ such that:}
\]
\begin{enumerate}
    \item \( a^{n-1} \equiv 1 \pmod{n} \),
    \item \( a^{(n-1)/p} \not\equiv 1 \pmod{n} \) for all prime divisors \( p \) of \( n-1 \).
\end{enumerate}

The Pratt certificate works recursively: to prove that \( n \) is prime, we must prove that all prime factors of \( n-1 \) are also prime. This recursion ends at small primes that are trivially verifiable.

\subsection*{Pseudocode}

\textbf{Pratt Primality Certificate}

% \texttt{Input: Number \( n \)}  
% \texttt{Output: A certificate of primality for \( n \)}

\begin{quote}\ttfamily
1. If \( n \leq 1 \), return "Not Prime" \\
2. Compute \( n-1 \) and find its prime factorization: \( n-1 = \prod p_i^{e_i} \) \\
3. Choose a base \( a \) such that \( 1 < a < n \) and compute: \\
\hspace*{2em} a. \( a^{n-1} \mod n \) \\
\hspace*{2em} b. \( a^{(n-1)/p_i} \mod n \) for all prime factors \( p_i \) \\
4. If \( a^{n-1} \not\equiv 1 \pmod{n} \) or any \( a^{(n-1)/p_i} \equiv 1 \pmod{n} \), return "Composite" \\
5. Recursively verify the primality of each \( p_i \) \\
6. Return the certificate: \( (n, a, \{(p_i, e_i)\}, \{p_i \text{'s certificates}\}) \)
\end{quote}

\subsection*{Advantages}

\begin{itemize}
    \item \textbf{Deterministic Proof}: Provides a verifiable certificate of primality.
    \item \textbf{Recursive Verification}: Ensures complete rigor by verifying all factors of \( n-1 \).
    \item \textbf{Polynomial-Time Verification}: Once generated, the certificate can be verified in \( O(\log(n)^2) \).
\end{itemize}

\subsection*{Disadvantages}

\begin{itemize}
    \item \textbf{Computationally Intensive}: Factorizing \( n-1 \) is expensive, especially for large \( n \).
    \item \textbf{Recursive Complexity}: The recursion grows with the number of prime factors in \( n-1 \), increasing the computation time.
\end{itemize}

\subsection*{Advantages Over Rabin-Miller Test}

\begin{itemize}
    \item Unlike Rabin-Miller, Pratt certificates are \emph{deterministic} and provide an absolute proof of primality.
    \item Certificates can be stored and reused, making verification efficient and independent of the original computation.
\end{itemize}

\subsection*{Behavior for Large Numbers}

\begin{itemize}
    \item The method remains deterministic but becomes computationally expensive for large primes due to the factorization of \( n-1 \).
    \item Large numbers with smooth \( n-1 \) (i.e., small prime factors) are easier to handle.
    \item For cryptographic applications, this method is often impractical due to its recursive nature.
\end{itemize}

\subsection*{Expected Error}

\begin{itemize}
    \item \textbf{Error Rate}: None; Pratt provides a deterministic proof.
    \item \textbf{Worst-Case Complexity}: Depends on the size and factorization of \( n-1 \).
\end{itemize}

\subsection*{Example}

Let \( n = 23 \). Then \( n-1 = 22 = 2 \times 11 \). The base must be chosen per prime: \( a = 2 \) is \emph{not} valid for \( 23 \), because \( 2^{11} \equiv 1 \pmod{23} \) (it has order \( 11 \), not \( 22 \)). Take \( a = 5 \):
\begin{enumerate}
    \item \( 5^{22} \equiv 1 \pmod{23} \), \( 5^{22/2} = 5^{11} \equiv 22 \not\equiv 1 \pmod{23} \) and \( 5^{22/11} = 5^{2} \equiv 2 \not\equiv 1 \pmod{23} \).
    \item The prime factors are \( 2 \) (trivially prime) and \( 11 \). For \( 11 \): \( n-1 = 10 = 2 \times 5 \) and \( a = 2 \) works, since \( 2^{10} \equiv 1 \), \( 2^{5} \equiv 10 \not\equiv 1 \), \( 2^{2} \equiv 4 \not\equiv 1 \pmod{11} \); its factor \( 5 \) is certified in turn (\( 5 - 1 = 4 = 2^2 \), \( a = 2 \)).
    \item Certificate for \( n = 23 \):
    \[
    (23, 5, \{2, 11\}, \{(11, 2, \{2, 5\}, \{(5, 2, \{2\})\})\}).
    \]
\end{enumerate}
Our first Circom verifier used one global base for every prime in the chain, which cannot work: \( 2 \) is not a valid base for \( 23 \), \( 1933 \) or \( 2168827 \).

\subsection*{Conclusion}

The Pratt Primality Certificate is a deterministic method that rigorously proves the primality of a number. While computationally expensive, its recursive structure provides verifiable proof, making it a useful theoretical tool for understanding primality in cryptography and mathematics.

\section{Elliptic Curve Primality Proving (ECPP)}\label{sec:ecpp}

\subsection*{Algorithm Explanation}

The Elliptic Curve Primality Proving (ECPP) algorithm of Goldwasser--Kilian and Atkin--Morain is a deterministic method that, unlike Pratt, needs no structure in \( n-1 \). It rests on the following theorem.

\textbf{Theorem.} Let \( n \) be coprime to \( 6 \), let \( E: y^2 = x^3 + ax + b \) be a curve over \( \mathbb{Z}/n\mathbb{Z} \), \( P \) a point on it, \( k \) an integer and \( q \) a prime with \( q > (n^{1/4}+1)^2 \). If \( R = [k]P \) is an \emph{affine} point (every inverse met while computing it exists modulo \( n \)) and \( [q]R = O \), then \( n \) is prime.

\emph{Proof sketch.} Suppose \( n \) were composite and let \( p \) be a prime factor with \( p \le \sqrt{n} \). Reduced modulo \( p \), the point \( R \) is not the point at infinity, but \( [q]R = O \); since \( q \) is prime, \( R \) has order exactly \( q \) on \( E(\mathbb{F}_p) \). By Hasse's bound \( q \le \#E(\mathbb{F}_p) \le (\sqrt{p}+1)^2 \le (n^{1/4}+1)^2 \), contradicting the choice of \( q \). \qed

The group order \( m = \#E \) does not have to equal \( n-1 \) (that is the situation of Pratt's certificate, which uses the \emph{multiplicative} group); it is close to \( n \) by Hasse's bound, and the prover looks for a curve whose order factors as \( m = k \cdot q \) with \( q \) a large prime. The condition \( q > (n^{1/4}+1)^2 > \sqrt{n} \) means each level can at best halve the bit length of \( n \), so a certificate for a \( 64 \)-bit prime has about three levels.

Verification of one level (the certificate is \( (n, a, b, P, k, q) \) plus a certificate for \( q \)):
\begin{enumerate}
    \item Check \( \gcd(n,6)=1 \) and that \( P \) lies on \( E \) (the discriminant check turns out to be redundant given the size bound).
    \item Check \( q > (n^{1/4}+1)^2 \).
    \item Compute \( R = [k]P \) with the affine group law, checking every inverse; compute \( [q-1]R \) and check that it equals \( -R \), i.e.\ \( [q]R = O \).
    \item Recursively certify \( q \) (at the bottom, by trial division).
\end{enumerate}

\subsection*{Pseudocode}

\textbf{ECPP verification of one level}

\begin{quote}\ttfamily
1. If \( \gcd(n,6) \neq 1 \), reject \\
2. Check \( y_P^2 \equiv x_P^3 + a x_P + b \pmod{n} \) \\
3. Check \( q > (n^{1/4}+1)^2 \) \\
4. \( R \leftarrow [k]P \) by double-and-add; reject if any inverse does not exist \\
5. \( Q \leftarrow [q-1]R \) by double-and-add; reject if any inverse does not exist \\
6. Accept iff \( Q = -R \), i.e. \( [q]R = O \) \\
7. Recursively verify that \( q \) is prime
\end{quote}

\subsection*{Advantages}

\begin{itemize}
    \item \textbf{Deterministic Proof}: Provides rigorous proof of primality.
    \item \textbf{Polynomial-Time Verification}: The certificate can be verified in polynomial time.
    \item \textbf{Efficient for Large Primes}: ECPP is highly optimized for proving the primality of very large numbers.
\end{itemize}

\subsection*{Disadvantages}

\begin{itemize}
    \item \textbf{Complexity in Setup}: Requires careful selection of elliptic curves and points.
    \item \textbf{Computational Intensity}: The algorithm is computationally expensive due to the order computation and recursive primality checks.
    \item \textbf{Dependence on Elliptic Curve Theory}: Requires advanced mathematical knowledge for implementation.
\end{itemize}

\subsection*{Advantages Over Pratt and Rabin-Miller Tests}

\begin{itemize}
    \item Unlike Pratt, ECPP does not rely on the smoothness of \( n - 1 \) and is more practical for general numbers.
    \item ECPP provides a deterministic proof, unlike Rabin-Miller, which is probabilistic.
    \item For very large primes, ECPP is faster and more scalable than Pratt certificates.
\end{itemize}

\subsection*{Behavior for Large Numbers}

\begin{itemize}
    \item Outside a circuit, optimised implementations certify primes with thousands of digits; finding the certificate (point counting) is the expensive part, verifying it is cheap.
    \item Inside a zero-knowledge circuit verification is far from free: about nine modular multiplications per scalar bit, so a $64$-bit certificate already costs three times a $256$-bit Pocklington proof (Section~\ref{sec:noir}).
    \item The chain at best halves the bit length per level.
\end{itemize}

\subsection*{Expected Error}

\begin{itemize}
    \item \textbf{Error Rate}: None; ECPP provides deterministic proofs.
    \item \textbf{Worst-Case Complexity}: Depends on the selection of elliptic curves and the recursive depth.
\end{itemize}

\subsection*{Example}

Let \( n = 10007 \). A certificate level (found by random curve search and point counting, then checked by computer) is
\[
E: y^2 = x^3 + 1613x + 2151, \quad P = (3025, 8142), \quad k = 50, \quad q = 199 .
\]
Here \( 10^4 = 10000 \le n < 11^4 \), so \( r = 10 \) and \( (r+2)^2 = 144 \le q \), which implies \( q > (n^{1/4}+1)^2 \approx 121 \). Then
\[
R = [50]P = (211, 7768), \qquad [198]R = (211, 2239) = -R \quad (7768 + 2239 = 10007),
\]
so \( [199]R = O \). Since \( 199 \) is prime (trial division), \( n = 10007 \) is prime.

\subsection*{Conclusion}

ECPP is a state-of-the-art primality proving algorithm that combines the power of elliptic curves and modular arithmetic. Its scalability and rigorous proof make it ideal for cryptographic applications requiring absolute certainty of primality.


\section{Zero-Knowledge Circuits in Circom}

The circuits in \texttt{circom/} prove, for a public $n$ (up to $32$ bits), that the test accepts $n$. A circuit is only as good as the constraints it contains: a value computed with an unconstrained assignment (\texttt{<--}) can be set to anything by a malicious prover. The first version of these circuits computed every modular exponentiation that way, never constrained the output \texttt{isPrime} to be $1$, and compared values with $1-(x-1)^2$, which is not a boolean. All of this was rewritten; this section describes the final design.

\subsection*{A sound arithmetic library}

All values are $k$-bit integers with $k \le 125$. The bound is what makes the library sound: the equation $a\cdot b = q\cdot n + r$ has both sides below $2^{2k+1}$, which is smaller than the BN254 scalar field ($\approx 2^{253.6}$), so it holds over the \emph{integers} and not only modulo the field prime. The templates, in \texttt{lib/}, are:
\begin{itemize}
    \item \texttt{ModMul}: proves $r = ab \bmod n$ by constraining $ab = qn + r$ with $q < 2^k$ and $r < n$ (range checks by bit decomposition).
    \item \texttt{ModExp}: square-and-multiply over the $k$ bits of the exponent, about $4k^2 + 13k$ constraints. The quadratic growth in the bit width, and the linear growth in the number of bases or certificate entries, is what makes the circuits large.
    \item \texttt{IsZero}, \texttt{IsEqual}: genuinely boolean equality (the previous formula was not).
    \item \texttt{AssertBaseInRange}: bases must satisfy $2 \le a \le n-2$; bases $0$, $1$ and $n-1$ would pass the Fermat test vacuously. Consequently $n \ge 5$.
\end{itemize}
Every top-level circuit asserts \texttt{isPrime} $=1$, so a composite has no valid witness. A single field element cannot hold the $256$-bit numbers of the original project goal; going beyond $125$ bits needs multi-limb arithmetic (Section~\ref{sec:noir}).

\subsection*{The circuits}

\textbf{Fermat and Lehmann.} Per-base results are chained with $\mathrm{acc}_{i+1} = \mathrm{acc}_i \cdot \mathrm{result}_i$ from $\mathrm{acc}_0 = 1$. (The first version never multiplied in the result of the first base, so $a_0$ was not tested.)

\textbf{Rabin-Miller.} The decomposition $n-1 = d\cdot 2^r$ is derived inside the circuit and fully constrained: $r$ is one-hot encoded, $n - 1 = d \cdot 2^r$ and $d$ is odd, which pins $(d,r)$ uniquely, so a malicious prover cannot choose another decomposition (which would silently turn the test into the weaker Lehmann test). Squarings use \texttt{ModMul} directly. The first version never counted $a^d \equiv n-1$ as a pass (its loop started at $j=1$), and its sample input described $n = 561$ while claiming $n = 491$. The circuit shrank from $217{,}464$ to $64{,}972$ constraints while using ten bases instead of five.

\textbf{Pratt.} A certificate is a list of entries $(p_i, g_i, q_{i,0},\dots,q_{i,F-1})$ with $p_i - 1 = 2^s \prod_l q_{i,l}$ (checked as an exact integer equality). Each entry has its own base $g_i$ with $g_i^{(p_i-1)/2} \not\equiv 1$, $g_i^{p_i-1} \equiv 1$ and $g_i^{(p_i-1)/q}\not\equiv 1$ for every distinct odd factor $q$ (a derived ``same as previous'' flag, so a check cannot be skipped). Every non-padding $q$ must equal the prime of some entry. Because $q$ divides $p_i - 1$ it is smaller than $p_i$, so induction on the value of the primes proves every entry prime and no cycle check is needed. Unused entries are padded with the valid entry $(3, 2)$. Only $n$ is public; the certificate is private witness. The sample certificate of the first version was also incomplete: $3$, $7$ and $17$ appeared as factors without entries.

\subsection*{How the circuits were tested}

Each circuit is compared against a Python reference on random and adversarial inputs, and its witnesses are \emph{tampered with}: one wire of an honest witness is changed and the constraint system must reject it (a wire that was still assigned with \texttt{<--} survives this test). Finally the tests are \emph{mutation-checked}: each soundness-critical constraint is deleted from a copy, and the test suite must then fail. This found, among others, the skipped first base, the vacuous bases and the ignored case $a^d\equiv n-1$, and showed that a ``tamper $d$ by $\pm 1$'' test alone would not have caught a missing ``$d$ is odd'' check, because a coherent alternative decomposition silently weakens the test.

\section{Provable Primes and $N = p\cdot q$ in Noir}\label{sec:noir}

The goal of the project is a zero-knowledge proof that $N = p\cdot q$ with large primes $p$ and $q$. The Circom library is limited to $125$-bit numbers, and Rabin-Miller with fixed public bases is not sound against a prover who picks a strong pseudoprime to those bases (a sound version needs hash-derived bases and about $40$ of them for $80$-bit security, roughly $40 \times 78{,}793 \approx 3.1$ million gates per $256$-bit prime, extrapolated from the measured one-base circuit). We therefore used Noir with the \texttt{noir-bignum} library (\texttt{noir/}) and a deterministic method.

\subsection*{A Pocklington criterion}

\textbf{Criterion.} Let $f$ be prime with $f^2 > n$, and suppose some $y$ satisfies $y^f \equiv 1 \pmod n$ and $\gcd(y-1, n) = 1$. Then $n$ is prime.

\emph{Proof.} Let $p$ be any prime divisor of $n$. Modulo $p$, $y \not\equiv 1$ but $y^f \equiv 1$, so the order of $y$ is exactly $f$ ($f$ is prime), hence $f \mid p-1$ and $p > f > \sqrt n$. This holds for every prime divisor, so $n$ has a single prime factor: $n$ is prime. \qed

An honest prover builds each prime as $n = f\cdot e + 1$ from the previous one (Maurer's provable primes, permitted by FIPS~186 for RSA keys) and takes $y = a^e$. The circuit does \emph{not} need the relation $n-1 = fe$ or the base $a$; dropping them halved the circuit. A chain $16 \to 32 \to 64 \to 128 \to 256$ bits, with trial division by the primes up to $251$ at the $16$-bit base case, certifies a $256$-bit prime with no error probability. We checked the criterion exhaustively for every $n < 1500$ and every prime $f < 200$: no composite is accepted, every honest prime is, and without $f^2 > n$ composites slip through (e.g.\ $573$ of them below $1500$).

\subsection*{The circuits}

\begin{itemize}
    \item \texttt{prime\_chain}: a public $256$-bit $n$ is prime.
    \item \texttt{semiprime}: a public $512$-bit $N$ equals $p\cdot q$ for private distinct $256$-bit primes $p,q$, each with its own chain. The product is checked exactly in a $512$-bit integer type (no wraparound), together with $N<2^{512}$ and $p\ne q$. Only $N$ is public.
    \item \texttt{ecpp\_chain}: a public $64$-bit $n$ is prime, by the ECPP verification of Section~\ref{sec:ecpp} over the chain $64 \to 33 \to 17 \to 9$ bits.
\end{itemize}

Its price is that the prover must \emph{generate} the primes with the chain structure; ECPP can certify a prime issued by someone else but costs about $3\times$ more at $64$ bits than the $256$-bit Pocklington proof, and we could generate certificates (pure Python point counting) only up to about $64$ bits; its cost at $256$ bits was not measured.

\subsection*{Evidence and limits}

Every soundness-relevant assertion was mutation-checked against an attack that satisfies all the other assertions: for the Pocklington steps the key forgery is a composite $n = p_1p_2$ with $p_i = 1 + k_i f$ and $y$ of order $f$ modulo both factors, which passes everything except $f^2>n$; for the semiprime circuit, all five assertions are caught. For ECPP, an exhaustive model for $n \le 55$ (and sampling up to $221$) accepts no composite; the size bound is necessary, and the on-curve and discriminant checks are redundant for soundness (the group-law formulas never use $b$ and the size bound already excludes singular curves). Known gaps: the ECPP inverse checks and top-bit assertions could not be attacked at circuit level; the Barrett constant of \texttt{noir-bignum} is an unvalidated witness by design (it only steers witness generation); all bit widths are fixed.

\section{Conclusion and Limitations}

The first version of this project showed how primality tests map onto arithmetic circuits but its circuits did not constrain their arithmetic: a malicious prover could have ``proved'' that a composite number is prime. The final design constrains every value, enforces the result, and is tested adversarially. For $N = p\cdot q$ with $256$-bit primes the practical route is a deterministic Pocklington chain in Noir ($70{,}982$ gates, $0.41$~s), while the Circom circuits remain a tested $32$-bit reference. Open items: ECPP certificates beyond $64$ bits, a trusted ceremony file for the larger Groth16 circuits (no verified source was found for $2^{17}$ and $2^{18}$), a measured ECPP circuit at $256$ bits, and a formal review of the circuits.
